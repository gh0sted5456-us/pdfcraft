# Personal AI Assistant

AI Assistant is optional and off by default. Open it from All tools or command search, enable it, and connect **your own** account. No developer account, personal key, token, document text or conversation is included in the installer or ordinary settings. Opening the dialog does not contact an AI service.

## Connections

- **ChatGPT subscription:** Continue with ChatGPT opens OpenAI authorization in your browser. PdfCraft is an independent open-source native public client, using PKCE, fresh state/nonce, the loopback callback and the client ID issued by OpenAI. It does not read Codex or ChatGPT desktop credentials. Account selection is explicit. Models come from this account's public model catalog; inference uses the public Responses API with plan-usage consent. Limits and eligibility belong to the user's plan. Rejection or exhausted usage never falls back to API billing.
- **Claude subscription:** install the official native Claude Code CLI first, then sign in from PdfCraft. This uses a separate `CLAUDE_CONFIG_DIR` inside this user's PdfCraft Assistant data directory. Requests disable tools, MCP, hooks and persisted CLI sessions, and send reviewed PDF text through stdin. Environment API keys, OAuth overrides and cloud-provider flags are removed from the child process. An older CLI missing the required safety switches fails rather than silently dropping them.
- **OpenAI API / Claude API:** explicitly select the API provider and enter your personal key in the masked field. API billing is separate from chat subscriptions. PdfCraft stores keys in the current user's Windows Credential Manager, macOS Keychain or Linux Secret Service. An unavailable store returns an error; there is no plaintext-file fallback.

ChatGPT tokens also use that OS store, with bounded chunked records and an atomic manifest to preserve an old session if rotation fails. Only non-secret provider/model/account identifiers go into normal preferences. Disconnect removes PdfCraft's local session and attempts provider revocation when network access is permitted. If remote revocation cannot be confirmed, the UI says to disconnect PdfCraft in ChatGPT settings too. Claude logout affects the separate PdfCraft CLI profile.

## Chat and browser connections

The Assistant opens across the current document workspace, beneath PdfCraft's tabs and toolbars. It has a conversation area, a fixed message composer, a document context/privacy pane and a separate **Manage connections** view. The narrow layout folds document controls into a compact section. Use the window controls to minimize chat to PdfCraft's internal taskbar; restoring chat fills whichever document tab is current and clears stale PDF context. Restore down is available for a floating view. Enable connections explicitly. Native chat keeps up to six recent turns in memory (100 KB total, at most 8 KB reused in a follow-up); it never saves transcripts in preferences. New chat clears the conversation. Changing the provider, source PDF or reviewed page scope clears PdfCraft's reviewed context and native chat. It does not erase conversations already pasted into a provider website. Suggestions never modify the PDF.

**Browser chat** opens the official ChatGPT, Claude or Copilot website inside a Windows WebView2 child, only after **Open browser chat** is clicked. Each provider has a separate profile under this user's local `PdfCraft/Assistant/Browser` directory. It never imports Edge/Chrome cookies or a developer login. Sign in yourself; the provider's normal subscription and usage rules apply. The embedded browser exposes no PdfCraft file, automation or IPC bridge, restricts top-level navigation to provider/identity HTTPS origins, denies permission prompts and downloads, and blocks extra windows. Provider sites may reject embedded sign-in. Organization SSO on another origin and sites requiring popups need **Open in external browser**. The external browser is also the Linux/macOS fallback; the Windows embedded host currently belongs to the main PdfCraft window.

**Personal Copilot** uses browser chat, because Microsoft's documented Microsoft 365 chat API does not accept personal Microsoft accounts. No unsupported endpoint or cookie-to-token conversion is used. **Microsoft 365 Copilot** supports browser chat or an optional native preview API connection: your IT team must supply a public-client application ID and tenant ID and enable device-code sign-in. It requires an eligible work/school Copilot license, delegated `Sites.Read.All`, `Mail.Read`, `People.Read.All`, `OnlineMeetingTranscript.Read.All`, `Chat.Read`, `ChannelMessage.Read.All`, `ExternalItem.Read.All`, and `offline_access`. Review this broad Microsoft-required consent with IT. Global, GCC High and DoD endpoint selections remain separate; no tenant/credential fallback crosses clouds. These are configuration choices, not a claim of organizational approval. Tokens are stored in this user's OS credential store. Disconnect removes local tokens; it does not revoke tenant consent. Microsoft's beta API may change; license access and live native inference have not been verified here. Web grounding is disabled on each native request; organizational grounding can still apply.

## Confidential documents and pages

**PDF privacy — Confidential** in the Assistant labels the whole PDF or the chosen page scope. Organize Pages also has **Confidential** and **Allow AI** for selected pages. Save the PDF to retain the labels. Document-level and page labels are independent: clearing a page label cannot override a Confidential document, and clearing a document label leaves page flags intact. Undo/Redo supports label changes. Signing/certification/page locks still govern whether metadata can change; removing a signature may be necessary before relabeling a signed PDF.

The custom `/PdfCraftAIConfidential true` value lives in the catalog or page dictionaries. It is an app-enforced AI opt-out, not encryption, a standard classification or DRM; other readers may ignore/remove it. Malformed present values fail closed. Native AI extraction, reviewed-text requests, browser context preparation and automation all check these flags. A document-level flag becomes a page flag when pages are extracted/copied/imported into another PDF, so it cannot disappear through Organize Pages. Label changes cancel pending local workers and discard cached context. Nothing can recall data already sent, erase an existing clipboard copy, or prevent someone from manually uploading/copying a PDF through another interface.

## Read, review, send

PDF sharing is separately off by default. Enable **Share PDF context**, choose current/all/selected pages, then **Review PDF context**. This extracts locally from the current document state, with page markers and copy-permission checks. Read and remove sensitive passages before **Send**. Only the reviewed context, bounded recent chat and task/question go to the selected native provider. In browser mode, **Copy reviewed PDF context** copies a locally prepared prompt; explicitly paste it into the provider chat yourself. There is no automatic website submission or browser response scraping. Scans need OCR first; images and the PDF binary are not uploaded. Requests are bounded to 256 pages, 200 KB of reviewed text and an 8 KB question. An oversized source is refused rather than silently truncated.

Summaries, answers, translations and edit suggestions are read-only. Source text is marked untrusted in the instruction and prompt. No model tool or document-edit capability is supplied. Review accuracy and page citations yourself. A changed/switched document discards stale extracted text and answers. Cancel discards the eventual result; a request already transmitted may still count toward provider usage. Provider retention rules apply even though OpenAI requests set `store: false` and Claude CLI session persistence is disabled.

## Headless use

`doc_set_confidential` labels a document or selected pages; `doc_info.document.ai_privacy` reports document/page flags (pages are 1-based). `ai_browser_prepare` returns a fixed official URL and context for explicit review/paste, with `sent:false`; no browser is opened. `ai_prepare` extracts text locally without network. `ai_assist` takes `provider`, `model`, optional `account`, `task` (`summary`, `suggestions`, `ask`, `translate`), `question` and either `reviewed_text` or selected pages. Sending, model discovery and sign-in require explicit `pdfcraft-cli --network`. `ai_accounts` lists only PdfCraft's saved profiles. `ai_login_start` returns an authorization URL; open it and poll `ai_login_finish`, or cancel that pending login. `ai_claude_login` uses the separate official CLI profile. `ai_copilot_login_start` takes `client_id`, `tenant_id` and optional `cloud` (`global`, `government`, `defense`); it returns Microsoft's verification URL/user code, never tokens. Poll `ai_copilot_login_finish`, or cancel that attempt. `model` is optional only for Copilot, whose model Microsoft controls. `ai_disconnect` removes a selected connection. `ai_key_connect` imports only the explicitly selected provider's matching environment variable; keys are never tool arguments or results. Automation does not implicitly import environment keys for inference.

Synthetic checks cover bounded text extraction, no PDF edits, the network gate, strict callback state/client checks, API/subscription separation, incomplete streams, token-store rotation rollback, disabled CLI execution features, settings privacy and stale worker results. Live provider sign-in/inference, native Linux/macOS credential stores and Claude CLI login have not been exercised on this machine. The WASM build displays a desktop-connection notice. New assistant labels are currently English. This addresses the requested workflow behind upstream #4150 and #3112 without adopting conflicting PR #182's older settings/key storage.
